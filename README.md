## つまずきマップとは ― 原理の説明

### 基本の考え方

「つまずきマップ」は、**クラスが英語のどの分野でつまずいているかを正答率で可視化した図**です。仕組み自体は単純で、特別な統計手法は使いません。

第一に、テストの各問題に「その問題が何を問うているか」を示すタグを付けます。例えば関係詞を問う問題には `relative-clause`、語彙を問う問題には `vocabulary` というタグを付けます。1つの問題に複数のタグが付くこともあります。

第二に、生徒の正誤データを集計し、タグごとに「そのタグが付いた問題群のクラス平均正答率」を計算します。関係詞タグの問題の正答率が35%、語彙タグが75%、というように出ます。

第三に、これを棒グラフにします。正答率が低いタグ＝クラスの弱点です。この図が「つまずきマップ」です。関係詞が35%なら「このクラスは関係詞でつまずいている」と読み取れます。

### AIが関わる3つのポイント

**ポイント1：タグ付けの自動化と、その信頼性の検証。** 問題へのタグ付けを教員が手作業で行うのは負担が大きいため、生成AIに任せられないかを検討します。ただしAIのタグ付けが正確とは限らないので、教員が付けたタグとAIが付けたタグを突き合わせ、どの程度一致するか（＝AIをどこまで信頼できるか）を測定します。一致度の指標にはJaccard係数（共通タグ数÷全タグ数。1.0で完全一致）を使います。

このアプリでは、教員のタグ付け作業を完全に省略してAIタグだけでマップを作ることもできます。その場合、マップ上の各タグの横に由来バッジ（教員手動／AIコピー／AI修正／混在）が表示され、「このマップが何のタグで作られたか」が一目で分かるようになっています。

**ポイント2：弱点に連動した問題の自動生成。** つまずきマップで判明した弱点に基づき、その分野を強化する問題を生成AIで作ります。正答率が低いタグほど多く出題する計画を立て、生成AIにそのまま渡せる指示文（プロンプト）を組み立てます。難易度（中1〜高3）を選んだり、参考にしたい既存問題を「例示」として渡すことで、生成精度を上げられます。

**ポイント3：AIへのフィードバックによる精度改善。** 一度タグ付けさせたAIに対して、教師タグと異なっていた問題を「なぜ間違いか」と一緒に継続的な会話の中でフィードバックすることで、その後のタグ付け精度を改善できます。STEP 3では不一致問題の一覧と、それをそのまま貼り付けられるフィードバック用プロンプトを自動生成します。これにより「AIタグ付け → 教師が確認 → ミスをフィードバック → 再タグ付け」というループを回すことができます。

### 時系列での効果測定

テストを複数回行うと、つまずきマップの変化を追えます。「第1回で関係詞35%だったのが、補習を挟んだ第3回で58%に上がった」という推移を折れ線グラフで可視化することで、弱点に連動した指導の効果を測定できます。

ある回にそのタグの問題がなければ、折れ線はそこで途切れます。再びそのタグが出題された回でまた線がつながります。出題回数が全回に満たないタグには「出題 2/3回」のような頻度注記が付き、変化の判断に注意が必要なタグを識別できます。

### クラス単位と個人単位

つまずきマップは、クラス全体の平均でも、生徒一人ひとりでも作れます。クラスのマップは「このクラスはどの分野が弱いか」を、個人のマップは「この生徒はどの分野が弱いか」を示します。集計の仕組みは同じで、対象を全員にするか特定の生徒にするかだけが違います。個人マップには、比較のためクラス平均の位置も重ねて表示されます。

個人単位では、タグ別の弱点に加えて「クラス内偏差値」も表示できます。偏差値は外部模試と同じく、総合得点（全問の正答率）に基づくクラス内での相対位置で、`50 + 10 × (本人の正答率 − クラス平均) / 標準偏差` で計算します。タグ別の弱点はつまずきマップで見られるので、偏差値はあくまで総合的な位置づけを示すものとして使います。

ただし偏差値が意味を持つのは、**全員が同じ問題を解いた「共通テスト」の回だけ**です。生徒ごとに違う問題を解く「個人別問題」の回は、解いた問題自体が異なるため、点数を比べても相対位置の指標にはなりません。そのためアプリは各テスト回を「共通テスト」と「個人別問題」に区別し、偏差値・順位は共通テストの回でのみ表示します（個人別問題の回はタグ別正答率＝弱点把握には使われますが、偏差値の対象からは外れます）。

### ダミーモードの意義

このツールには、実際の生徒データを使わずに動かせる「ダミーモード」があります。仮想の生徒に「タグ別の理解度」をあらかじめ設定し、その値に従って正誤データを確率的に生成します。

ダミーモードの価値は、**システムの妥当性を、生徒に負担をかけずに検証できる**点にあります。特に「パラメータリカバリー」と呼ぶ検証では、最初に設定した理解度（真値）を、つまずきマップが正答率から正しく復元できるかを確認します。真値を知っているのはダミーだからこそ可能な検証で、実際の生徒では「本当の理解度」が不明なため原理的にできません。

なお、ダミーモードでテスト回ごとに正答率が上がっていくのは「学習の伸び」スライダーで設定したパラメータが各タグ一律に効いた結果で、問題自動生成での弱点補強の結果ではありません。実際の指導効果のシミュレーションではなく、「学習が一様に進む」という単純化したモデルです。

## Webアプリの使い方

`tsumazuki_webapp_v3.html` をブラウザで開くだけで動きます。インストール不要、サーバ不要、通信もしません。

### 2つのモード

画面上部のボタンで「ダミーモード」「本番モード」を切り替えます。

**ダミーモード**は、仮想クラスのデータでシステムを検証するモードです。実在の生徒データは使いません。STEP 1〜5（データ生成・つまずきマップ・AIタグ検証・パラメータリカバリー・問題自動生成）をすべて実行できます。

**本番モード**は、実際の生徒の解答を入力して分析するモードです。STEP 1〜3 と STEP 5 を実行できます（真値が存在しないため STEP 4 のパラメータリカバリーは省略されます）。入力した成績データはブラウザ内だけで処理され、外部に送信されません。

### ダミーモードの手順

STEP 1で、生徒数・テスト回数・問題数・学習の伸びなどをスライダーで設定し、「ダミークラスを生成」を押します。生徒数は3〜40人、テスト回数は1〜6回の範囲で設定できます。

STEP 2で、つまずきマップが表示されます。上部の「クラス全体／個人別」タブで表示を切り替えられます。クラス全体では、テストが複数回ある場合、(1) 全回累計のつまずきマップ、(2) 各回のマップ（◀▶で切り替え）、(3) 第1回から最終回への変化表、(4) 正答率の推移（折れ線）、の順に出ます。個人別では、◀▶またはプルダウンで生徒を選ぶと、その生徒のつまずきマップ（クラス平均を重ねて表示）と、共通テストに基づく総合得点・クラス内偏差値・順位が表示されます。

STEP 3で、AIが付けたタグと教員タグの一致度（Jaccard係数）が表示されます。ダミーモードでは「分詞↔関係詞」「推論↔指示語」をAIが混同しやすく仕込んであり、その傾向が再現されることを確認できます。

STEP 4で、パラメータリカバリーの結果が表示されます。最初に設定した理解度と、マップが推定した値の一致度を散布図と数値（相関、MAE、RMSE）で確認できます。

STEP 5は2つのパートに分かれます。STEP 5-Aは累計つまずきマップに基づく弱点連動の出題計画と生成プロンプト、STEP 5-Bはつまずきマップに依存しない通常問題の作成です。STEP 5-Aは「クラスの弱点／個人の弱点」を切り替えられ、個人を選ぶとその生徒の弱点に連動した出題計画になります。両パートとも、難易度（中1〜高3）の選択は任意で、未選択なら標準レベルが用いられます。

### 本番モードの手順

**(STEP 1) 解答データの入力。** 生徒の解答を入力します。「表に手入力」（セルをクリックして○→×→未入力 を切り替え）と「CSVを読み込む」の2方式があります。複数回のテストはタブで切り替えて入力でき、CSVは `test_id` 列でテスト回を区別します。

**(STEP 1) テスト回の種別。** 各テスト回には「共通テスト（全員が同じ問題）」か「個人別問題（生徒ごとに違う問題）」の種別をラジオで指定します。タブに「共」「個」のバッジが表示されます。偏差値・順位は共通テストの回でのみ算出されます（個人別問題は問題が異なるため偏差値の母集団になりません）。「回を追加」で新しく作る回は、弱点補強の結果を記録する想定で初期値が「個人別問題」になっていますが、共通テストに切り替えられます。

**(STEP 1) 教員タグの設定（3通り）。**

- **(a) モーダルで手入力** ― 表のヘッダ（Q1, Q2…）をクリックすると表示されるモーダルで、タグをチェック式で選ぶ。
- **(b) 問題タグCSVを読み込む** ― 「CSVを読み込む」タブから取り込む。形式は後述。
- **(c) AIタグをコピー** ― STEP 1b でAIに付けさせたタグを「AIタグを教師タグとして使う」ボタンでそのままコピーする。教員のタグ付け作業を省略してマップを自動作成できます。

**(STEP 1b) AIにタグを付けさせる。** AIにタグ付けを依頼するプロンプトを自動生成できます。

- **(a) PDFアップロード** ― 生成AIに問題のPDFをアップロードしてから、生成されたプロンプトを送る。
- **(b) 問題文を貼り付け** ― 「①問題文を貼り付け」欄に英文と設問を貼り付ける。プロンプトに自動で挿入されます。

両方併用も可能です。PDFは画像化された問題・段組み・特殊フォントなどでAIが正しく読み取れないことがあるので、その場合はテキスト貼り付けに切り替えてください。

AIの返答（`Q1: tag;tag` 形式）を取り込み欄に貼り付けると、AIタグとして保存されます。必要なら「AIタグを教師タグとして使う」を押せば、そのまま教師タグにもコピーされます。タグの由来（教員手動／AIコピー／AI修正）は内部で記録され、STEP 2のマップ上に表示されます。

**(STEP 1) 問題の分割（サブ問）。** 1つの問題が複数のスキルを問う場合（例：関係詞と語彙の両方）、問題を Q1-a・Q1-b のようにサブ問へ物理的に分割できます。分割後は各サブ問の正誤を独立して入力でき、タグも1つずつ割り振られます。

- **手動分割** ― 問題のヘッダ（Q1 など）をクリックしてタグピッカーを開き、タグを2つ以上選択すると「Nタグで分割」ボタンが有効になります。確定すると Q1-a・Q1-b…に分割され、元の正誤が全サブ問にコピーされます。
- **結合（元に戻す）** ― サブ問のヘッダをクリックすると「Q1 に結合」ボタンが表示されます。全兄弟サブ問をまとめて1問に戻します。
- **AIタグ取り込み時の自動提案** ― AIが複数タグを付けた問題を検出し「Q2（関係詞・語彙 → 2分割）」のように列挙して分割を提案します。OK を押すと一括分割し、タグを教師タグにもコピーします。
- 分割はグレー背景・青い左ボーダーでサブ問を視覚的に区別します。スライダーの「大問数」はサブ問を除いた親問題の数で設定します。
- 分割できるのは**共通テストの回のみ**です（個人別問題回は非対応）。

**(STEP 3) AIタグ検証とフィードバック。** AIタグと教師タグの一致度（Jaccard係数）の確認に加えて、不一致問題の一覧と**フィードバック用プロンプトの自動生成**が行えます。詳細は後述の「AIタグへのフィードバック」セクションを参照してください。

**(STEP 5)** ダミーモードと同じく問題自動生成を実行します。STEP 5-A（弱点連動の出題計画）はデータ入力後に、STEP 5-B（通常問題の作成）は生徒データ未入力でも使えます。

生成した個人別問題を生徒に解かせた結果は、STEP 1で新しいテスト回（個人別問題）として記録すると、STEP 2の推移で弱点が改善したかを確認できます。これにより、共通テストで弱点把握 → 個人別問題で補強 → 次の共通テストで効果測定、という研究のループを回せます。

## データの保存と読み込み

本番モードでは、入力したすべてのデータ（解答・教師タグ・AIタグ・問題文・テスト回設定）を保存し、後日そのまま再開できます。保存方法は2系統あります。

### 自動保存（ブラウザ）

本番モードで操作するたびに、データがブラウザに自動保存されます。ページを閉じて再度開いても前回の状態から再開できます。

- 画面上部の保存バーに「**自動保存 ON**」と表示されているときに有効です。
- 「自動保存 ON/OFF」ボタンでいつでも切り替えられます。ON にした瞬間に即時保存されます。
- 最終自動保存の時刻が保存バーに表示されます。
- 保存後に変更を加えると「**未保存の変更あり**」バッジが点滅して知らせます。

> **注意：** ブラウザの自動保存はそのブラウザ・端末にのみ保存されます。別の端末に引き継ぐ場合や、長期保管・データ分析用途には後述のJSON保存またはCSV保存を使ってください。

### JSON保存（完全バックアップ）

画面上部の保存バーの「**JSONで保存**」ボタンを押すと、現在のセッション全体を1つのJSONファイルに書き出します。

- 保存されるもの：解答データ（全テスト回・全生徒）、教師タグ、AIタグ、タグの由来情報、問題文テキスト、テスト回の種別・問題数などの設定すべて。
- ファイル名は `tsumazuki_session_YYYY-MM-DD.json` 形式で日付入りになります。
- 復元するには「**JSONを読み込む**」ボタンでファイルを選択します。保存日時が確認ダイアログに表示されます。
- JSON 1ファイルで完全復元できるため、**長期保管や端末間の引き継ぎ**に適しています。

### CSV保存（個別・分析用途）

「CSVを読み込む」タブに移動すると、上部に保存ボタンが2つあります。

| ボタン | 保存ファイル名 | 保存内容 |
| --- | --- | --- |
| 解答データをCSV保存 | `responses_saved.csv` | 全テスト回・全生徒の正誤データ |
| タグをCSV保存（教師・AI） | `question_tags_saved.csv` | 教師タグ・AIタグ・タグ由来情報 |

CSVは**Excelや他のツールでの集計・データ分析**に使えます。JSONと違い人間が読み書きできる形式なので、データを直接確認・修正したいときにも便利です。

読み込みは同じタブ内のドロップゾーンに保存したファイルをドラッグするだけです。解答CSVとタグCSVを両方読み込めば、JSONと同様の完全復元ができます。

### 3種の保存方法の使い分け

| 用途 | 推奨 |
| --- | --- |
| 作業を中断して翌日再開する | 自動保存（何もしなくてOK） |
| 別の端末に引き継ぐ | JSONで保存 → 相手端末でJSONを読み込む |
| 長期保管・バックアップ | JSONで保存（1ファイルで完結） |
| Excelや分析ツールで集計する | CSVで保存 |
| タグ付けのみ他者に渡す | タグCSVで保存 |

## 保存されるデータの形式（CSV詳細）

### 解答データCSV

**形式：** `test_id, question_id, student_id, correct`

- `test_id` ― `test01`, `test02`, … の形式でテスト回を区別します。
- `correct` ― 正解が `1`、不正解が `0`。
- **共通テスト回**の `question_id` は `Q01`, `Q02`, … 形式。サブ問がある場合は `Q01a`, `Q01b`, … 形式。
- **個人別テスト回**の `question_id` は `S01_Q01`, `S01_Q02`, … 形式（生徒IDと問題番号をアンダースコアで結合）。

```csv
test_id,question_id,student_id,correct
test01,Q01,S01,1
test01,Q01,S02,0
test02,S01_Q01,S01,1
test02,S02_Q01,S02,0
```

読み込み時は `question_id` の形式を自動判定し、`SXX_QYY` 形式の行を含む回は個人別テスト回として復元します。成功メッセージに「テスト3回（共通2・個人別1）× 生徒30名」のように内訳が表示されます。

### 問題タグCSV

**形式：** `test_id, question_id, teacher_tags, ai_tags, teacher_source`

- `teacher_tags` ― 教師タグ。セミコロン区切り。例：`relative-clause;vocabulary`
- `ai_tags` ― AIタグ。セミコロン区切り。空欄可。
- `teacher_source` ― タグの由来。`manual`（手入力）/ `ai-copy`（AIコピー）/ `ai-edited`（AI後に編集）/ 空欄。
- `test_id` 列は省略可能（省略時は `question_id` の形式に応じて全該当回に適用）。

```csv
test_id,question_id,teacher_tags,ai_tags,teacher_source
test01,Q01,relative-clause;vocabulary,relative-clause,manual
test01,Q02,tense,tense,ai-copy
test02,S01_Q01,inference,,manual
```

`#` で始まる行はコメントとして読み飛ばされます。未知のタグはスキップされメッセージで通知します。

## AIタグへのフィードバック

本番モードの STEP 3 では、AIタグ付けの精度を継続的に改善するためのフィードバック機能を利用できます。

### フィードバックの考え方

生成AIへのタグ付け依頼（STEP 1b）を「1回限りのやりとり」で終わらせるのではなく、**同じ会話を継続して使い続ける**ことでAIがタグ付けの傾向を学習し、次第に精度が上がることが期待できます。

```
STEP 1b でタグ付けを依頼
        ↓
STEP 3 でAIタグと教師タグを照合
        ↓
不一致問題をフィードバック用プロンプトにまとめる（自動生成）
        ↓
継続中の会話に貼り付けてAIにミスを認識させる
        ↓
次の問題セットのタグ付けへ
```

### STEP 3 の操作手順

1. STEP 1b でタグ付けプロンプトを生成し、AIに送って返答を取り込んでおく。
2. STEP 1 で教師タグを設定する（モーダル手入力またはCSV読み込み）。
3. 「この内容で分析する」を押して STEP 3 へ進む。
4. STEP 3 に**タグ不一致の問題テーブル**が表示される。各行には問題番号・教師タグ（正解）・AIタグ・見落とし（赤）・過剰付与（黄）・問題文プレビューが含まれます。
5. 「フィードバック用プロンプトを生成」ボタンを押すとコピー可能なプロンプトが展開される。
6. プロンプトをコピーし、STEP 1b でタグ付けを依頼した**継続中の会話**に貼り付ける。

全問一致の場合は「フィードバックは不要です」と表示されます。

### フィードバック用プロンプトの構成

- タグ一覧の再提示
- 問題ごとのフィードバックブロック（問題文・正解タグ・AIタグ・見落とし／過剰付与の説明）
- 締めの依頼（「修正方針を理解したら了解と答えてから次のタグ付けに備えてください」）

問題文は STEP 1b の「①問題文を貼り付け」欄の内容から自動抽出されます。貼り付けていない場合は問題番号とタグのみになります（問題文なしでも機能します）。

## 生徒向けAI弱点補強（QRコード配布）

本番モードの STEP 5-A では、教師がクラス全員分の弱点補強プロンプトをまとめて生成し、QRコードでテスト返却時に配布できます。これにより、生徒は自分の弱点分野に特化したAI学習をすぐに始められます。

### 背景と位置づけ

生成AIを使った英語学習（ロールプレー・教材作成・添削など）は成人学習者には有効ですが、中高生には「自分の弱点の言語化」と「適切なプロンプトの設計」という二つの前提が崩れがちです。つまずきマップは、テスト結果から弱点を客観的に診断する部分を教師側の仕組みが担い、弱点に連動したプロンプトを自動生成して生徒に手渡すことで、この障壁を取り除きます。

### STEP 5-A での操作手順

1. STEP 1 で解答データとタグを入力し、「この内容で分析する」を押す。
2. STEP 5 → 「個人の弱点」タブを選ぶ。
3. 難易度（任意）を選んだ上で「全N人分のプロンプトを生成」ボタンを押す。
4. 生徒ごとのカードが一覧表示される。各カードには以下が含まれます。
   - 生徒ID・総合正答率バッジ（赤/黄/緑）・弱点タグのピル表示
   - 「コピー（完全版）」― 詳細な指示を含む完全プロンプト
   - 「QRコード（簡易版）」― スキャンしてAIにすぐ貼り付けられるQR
   - 「QR画像を保存」― PNG形式でダウンロード

### 2種類のプロンプト

| | コピー（完全版） | QRコード（簡易版） |
|---|---|---|
| 内容 | 弱点タグ・問題数・出力形式・難易度の詳細指示（日本語） | 弱点タグ・問題数・最小限の指示（ASCII英語） |
| 文字数 | 1000字程度 | 300字以内 |
| 用途 | 教師が印刷・メール等で配布 | 生徒がスマホでスキャン→即ペースト |

QRコードは**ASCII英語のみ**で記述されています。これはQRコードライブラリが日本語を内部で約6倍に換算するため容量を超えるという技術的制約への対応です。AIはこの英語指示でも正確に日本語で問題・解説を出力します。

### 生徒の利用フロー

```
テスト返却（QRコード付き返却用紙）
        ↓
スマホでQRをスキャン
        ↓
テキストをコピーして ChatGPT / Claude に貼り付け
        ↓
弱点タグに特化した読解問題が生成される
        ↓
問題を解いて解説を確認
        ↓
（次回テストで同タグの正答率が STEP 2 の推移グラフで上がったか確認）
```

### 完全版プロンプトの構成

- 生徒IDと弱点タグ（正答率・優先度付き）
- 各弱点タグにつき3問、合計最大9問の依頼
- 問題形式（英文パッセージ＋4択）・使用言語の指定
- 問題部分と解答・解説を分離する出力指示（問題のみ先に出力し、そのまま生徒に配布できる形式）

弱点がない生徒（全タグ70%以上）は「弱点なし」と表示され、プロンプトは生成されません。

### なぜQRコードでインタラクティブな問題演習UIは表示できないか

QRコードに格納できるのはテキスト（プロンプト）のみです。GoogleのAIモード（AI Overview / Gemini）を含め、現在のAIチャットサービスはプロンプトの指示でブラウザにラジオボタンや入力フィールドを直接レンダリングすることはできません。ChatGPT の Canvas や Claude の Artifacts はHTMLを生成・表示できますが、QRコードからの起動時に自動的に演習UIを立ち上げる標準的な手段は現時点では存在しません。このため、本機能はプロンプト配布に留めています。

### 運用上の留意点

- 生徒が直接AIサービスを利用する場合は、各サービスの年齢規約（多くは13歳以上、一部18歳以上）と勤務校のAI利用ポリシーを事前に確認し、必要に応じて保護者の同意を得てください。文部科学省ガイドラインVer.2.0は「教師の適切な指導監督の下で利活用させることが必要」としています。
- AIが生成した問題には誤りが含まれることがあります。重要な場面では教師が事前に内容を確認することを推奨します。
- つまずきマップが出力するのはプロンプト（テキスト）のみです。AIサービス本体は内蔵していないため、どのサービス・どの運用形態に載せるかを学校側で選べます。

## Pythonスクリプトの使い方

実行には Python 3 と以下のライブラリが必要です。

```
pip install pandas openpyxl matplotlib japanize-matplotlib
```

### ダミーデータで一連の検証を行う場合

```
python3 generate_dummy.py          # dummy_data.xlsx と dummy_truth.csv を生成
python3 analyze.py dummy_data.xlsx # つまずきマップ等を出力
python3 verify_recovery.py         # パラメータリカバリーの図とレポートを出力
```

`analyze.py` はテスト回数に応じて出力を切り替えます。2回以上の場合は `tag_accuracy_timeseries.png`（折れ線グラフ）と `tag_change_report.txt`（変化レポート）も自動生成されます。個人別集計として `student_deviation.csv`（偏差値・順位）、`student_deviation.png`（偏差値分布図）、`student_tag_accuracy.csv`（個人つまずきマップ）も出力されます。

### 実際の生徒データを分析する場合

1. `tsumazuki_template.xlsx` を開き、questions シートと responses シートに入力
2. `python3 analyze.py tsumazuki_template.xlsx` を実行

## タグの変更方法

使用するタグ（語彙・関係詞など）を増減・改名したい場合：

- **Webアプリ**: `tsumazuki_webapp_v3.html` をテキストエディタで開き、`TAG_CONFIG` という配列（ファイル上部のコメント「タグを変更したいときは…」の箇所）を編集します。各行が1タグで、英語名・日本語名・ダミー用初期理解度を持ちます。行を増減すればタグが増減します。
- **ターミナル版**: `generate_dummy.py` の `TAG_CONFIG` を同様に編集します。
- タグを増やしたら、問題数（Webアプリのスライダー、または `N_QUESTIONS_PER_TEST`）も十分大きくしてください。タグ数の3〜4倍程度が目安です。
- WebアプリとExcelテンプレート（tag_master シート）は自動連動しません。両方を使う場合はタグ体系を手動で揃えてください。

## 注意

- Webアプリとターミナル版は乱数生成器が異なるため、同じ設定でも数値は完全には一致しません（モデルの挙動・弱点の序列は一致します）。発表資料に載せる確定値はターミナル版で固定することを推奨します。
- 生徒の成績データはセンシティブな個人情報です。校外のサービスで扱う前に、勤務校の個人情報取り扱い規程を確認してください。
- ブラウザの自動保存データは、ブラウザのキャッシュ削除や「プライベートモード」での使用時には保存されません。重要なデータは定期的にJSONまたはCSVで手元に保存してください。
