# つまずきマップ研究 ― 成果物一式

英語読解のAI活用授業を、研究会発表向けに実践・検証するためのツール群です。
ターミナルで動くPythonスクリプトと、ブラウザで動くWebアプリの2系統があります。

## ファイル一覧

| ファイル | 種別 | 役割 |
|---|---|---|
| `tsumazuki_webapp_v2.html` | Webアプリ | これ1つで全工程。ダミー/本番モード対応 |

## つまずきマップとは ― 原理の説明

### 基本の考え方

「つまずきマップ」は、**クラスが英語のどの分野でつまずいているかを正答率で可視化した図**です。仕組み自体は単純で、特別な統計手法は使いません。

第一に、テストの各問題に「その問題が何を問うているか」を示すタグを付けます。例えば関係詞を問う問題には `relative-clause`、語彙を問う問題には `vocabulary` というタグを付けます。1つの問題に複数のタグが付くこともあります。

第二に、生徒の正誤データを集計し、タグごとに「そのタグが付いた問題群のクラス平均正答率」を計算します。関係詞タグの問題の正答率が35%、語彙タグが75%、というように出ます。

第三に、これを棒グラフにします。正答率が低いタグ＝クラスの弱点です。この図が「つまずきマップ」です。関係詞が35%なら「このクラスは関係詞でつまずいている」と読み取れます。

### AIが関わる2つのポイント

つまずきマップ自体は単なる正答率の集計ですが、ここに生成AIを組み合わせる点に研究としての新しさがあります。

**ポイント1：タグ付けの自動化と、その信頼性の検証。**
問題へのタグ付けを教員が手作業で行うのは負担が大きいため、生成AIに任せられないかを検討します。ただしAIのタグ付けが正確とは限らないので、教員が付けたタグとAIが付けたタグを突き合わせ、どの程度一致するか（＝AIをどこまで信頼できるか）を測定します。一致度の指標にはJaccard係数（共通タグ数÷全タグ数。1.0で完全一致）を使います。

**ポイント2：弱点に連動した問題の自動生成。**
つまずきマップで判明した弱点に基づき、その分野を強化する問題を生成AIで作ります。正答率が低いタグほど多く出題する計画を立て、生成AIにそのまま渡せる指示文（プロンプト）を組み立てます。

### 時系列での効果測定

テストを複数回行うと、つまずきマップの変化を追えます。「第1回で関係詞35%だったのが、補習を挟んだ第3回で58%に上がった」という推移を折れ線グラフで可視化することで、弱点に連動した指導の効果を測定できます。

### ダミーモードの意義

このツールには、実際の生徒データを使わずに動かせる「ダミーモード」があります。仮想の生徒に「タグ別の理解度」をあらかじめ設定し、その値に従って正誤データを確率的に生成します。

ダミーモードの価値は、**システムの妥当性を、生徒に負担をかけずに検証できる**点にあります。特に「パラメータリカバリー」と呼ぶ検証では、最初に設定した理解度（真値）を、つまずきマップが正答率から正しく復元できるかを確認します。真値を知っているのはダミーだからこそ可能な検証で、実際の生徒では「本当の理解度」が不明なため原理的にできません。

## Webアプリの使い方

`tsumazuki_webapp_v2.html` をブラウザで開くだけで動きます。インストール不要、サーバ不要、通信もしません。

### 2つのモード

画面上部のボタンで「ダミーモード」「本番モード」を切り替えます。

**ダミーモード**は、仮想クラスのデータでシステムを検証するモードです。実在の生徒データは使いません。STEP 1〜5（データ生成・つまずきマップ・AIタグ検証・パラメータリカバリー・問題自動生成）をすべて実行できます。

**本番モード**は、実際の生徒の解答を入力して分析するモードです。STEP 1〜3 と STEP 5 を実行できます（真値が存在しないため STEP 4 のパラメータリカバリーは省略されます）。入力した成績データはブラウザ内だけで処理され、外部に送信されません。

### ダミーモードの手順

STEP 1で、生徒数・テスト回数・問題数・学習の伸びなどをスライダーで設定し、「ダミークラスを生成」を押します。生徒数は3〜40人の範囲で設定できます。

STEP 2で、つまずきマップが表示されます。テストが複数回ある場合は、全回累計のマップ、各回のマップ（◀▶で切り替え）、第1回から最終回への変化、正答率の推移（折れ線）が順に出ます。

STEP 3で、AIが付けたタグと教員タグの一致度（Jaccard係数）が表示されます。

STEP 4で、パラメータリカバリーの結果が表示されます。最初に設定した理解度と、マップが推定した値の一致度を散布図と数値で確認できます。

STEP 5は2つのパートに分かれます。STEP 5-Aは累計つまずきマップに基づく弱点連動の出題計画と生成プロンプト、STEP 5-Bはつまずきマップに依存しない通常問題の作成です。STEP 5-Bでは出題するタグと問題数、難易度（中1〜高3）を手動で指定でき、第1回テストの作成や弱点補強に偏らない出題に使えます。本番モードでは、生徒データ未入力でもSTEP 5を開いてSTEP 5-Bを利用できます。

### 本番モードの手順

STEP 1で、生徒の解答を入力します。「表に手入力」（セルをクリックして○×を入力）と「CSVを読み込む」の2方式があります。複数回のテストはタブで切り替えて入力でき、CSVの場合は `test_id` 列でテスト回を区別します。問題ごとの教員タグは、3通りの方法で設定できます。(1) 表のヘッダ（Q1, Q2…）をクリックして表示されるモーダルで選択する、(2) CSV読み込み時に「問題タグCSV」（`question_id,teacher_tags` 形式）を別ファイルで取り込む、(3) STEP 1bでAIに付けさせたタグをそのまま教師タグとしてコピーする。

STEP 1bで、AIに問題のタグ付けを依頼するプロンプトを生成できます。問題はPDFアップロードと問題文貼り付けの両方の方法で渡せます。生成AIの返答（`Q1: tag;tag` 形式）を貼り付けるとAIタグとして取り込まれ、必要なら「AIタグを教師タグとして使う」ボタンでそのまま教師タグにコピーできます。これによりつまずきマップを自動作成できます。タグの由来（教員手動 / AIコピー / AI修正）は記録され、STEP 2のつまずきマップ上で各タグの横にバッジ表示されます。

STEP 2・3・5は、ダミーモードと同様につまずきマップ・AIタグ検証・問題生成を実行します。

## Pythonスクリプトの使い方

実行には Python 3 と以下のライブラリが必要です。
```
pip install pandas openpyxl matplotlib japanize-matplotlib
```

### ダミーデータで一連の検証を行う場合
```
python3 generate_dummy.py      # dummy_data.xlsx と dummy_truth.csv を生成
python3 analyze.py dummy_data.xlsx     # つまずきマップ等を出力
python3 verify_recovery.py     # パラメータリカバリーの図とレポートを出力
```

### 実際の生徒データを分析する場合
1. `tsumazuki_template.xlsx` を開き、questions シートと responses シートに入力
2. `python3 analyze.py tsumazuki_template.xlsx` を実行

## タグの変更方法

使用するタグ（語彙・関係詞など）を増減・改名したい場合：

- **Webアプリ**: `tsumazuki_webapp_v2.html` をテキストエディタで開き、
  `TAG_CONFIG` という配列（ファイル上部のコメント「タグを変更したいときは…」の箇所）
  を編集します。各行が1タグで、英語名・日本語名・ダミー用初期理解度を持ちます。
  行を増減すればタグが増減します。
- **ターミナル版**: `generate_dummy.py` の `TAG_CONFIG` を同様に編集します。
- タグを増やしたら、問題数（Webアプリのスライダー、または generate_dummy.py の
  `N_QUESTIONS_PER_TEST`）も十分大きくしてください。問題が少ないと一部のタグが
  出題されず欠損になります。
- WebアプリとExcelテンプレート（tsumazuki_template.xlsx の tag_master シート）は
  自動連動しません。両方を使う場合は、タグ体系を手動で揃えてください。

## 注意

- Webアプリとターミナル版は乱数生成器が異なるため、同じ設定でも数値は
  完全には一致しません（モデルの挙動・弱点の序列は一致します）。
  発表資料に載せる確定値はターミナル版で固定することを推奨します。
- 生徒の成績データはセンシティブな個人情報です。校外のサービスで扱う前に、
  勤務校の個人情報取り扱い規程を確認してください。
